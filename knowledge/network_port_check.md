# 网络与端口连通性检查

> 来源类型：自写整理（self_written）
> 来源说明：依据通用 Linux 网络工具行为整理
> 适用版本：通用
> 来源链接：https://man7.org/linux/man-pages/man8/ss.8.html
> 适用系统：linux_generic
> 更新日期：2026-11-17
> 核实状态：通用语义已核对公开资料；发行版默认值需现场取证

## 本机侧
- `ss -lntp` 查看监听端口与进程；服务"起了但访问不到"时先确认是否真的监听。
- `ip addr` 与 `ip route` 确认地址与默认路由；`nmcli` 适用于 NetworkManager 管理场景。

## 远端侧
- `ping` 只验证 ICMP，不等于 TCP 可达；`nc -zv <host> <port>` 或 `curl -v` 更能反映实际链路。
- 超时与拒绝含义不同：超时多为链路/防火墙丢包，拒绝多为端口未监听或被 reject。

## 常见叠加因素
防火墙（firewalld/nftables）与 SELinux 端口标签都可能拦截；`systemctl status firewalld` 与 `semanage port -l` 需一并确认。

## 判读
连通性问题需区分本机监听、路由、防火墙、对端服务四层，逐层排除比直接改配置更可靠。

## 安全注意事项

- 远程改网络前设置自动回滚；不要把管理端口直接暴露公网。

## 预期输出与判读

- `LISTEN` 只证明本机监听，外部可达还需排防火墙、安全组与绑定地址。

## 常见错误

- `ss` 有监听就认为外部可达：绑定地址与防火墙仍可能阻断。
- 只查本机防火墙：云安全组/上游 ACL 也会拦。
- 改地址不留回滚：远程会话断开后无法恢复。

## 排查思路

- 地址→路由→监听→本机策略→外部策略逐层验证。
- 用 `curl -v` 获取具体失败阶段。
